# ADR-0096：PubSub 与 Bucket Store 家族——三轴分立、连接注入与备份诚实面

日期：2026-11-04 立法（提案 §6；设计 `docs/design/2026-11-04-managed-data-services.md` §4/§6）｜ 状态：Accepted（实施随 B4/B5/B6；ADR-0029 用户域第三形态的全量复制先例）

## 背景

Kafka/NATS/对象存储托管服务全仓零存在。用户裁决（2026-11-04）：三引擎全进（NATS→silo→Kafka 批次序）。Database 的用户域第三形态（ADR-0029 决策 3：收敛环投影、不进 Deployment 状态机、不进 fleetly/system 受管域）证明可复制；本 ADR 裁决新家族的实体/轴/连接/凭证/备份面。

## 决策

1. **统一托管服务机制 + 家族特化（2026-11-05 用户裁决；红队二次翻案定形）**：三聚合三表三 RPC 面不变（词汇冻结，`pubsubs`/`bucket_stores` 表与 Database 同形——含 ADR-0094 version 列、ADR-0095 settings/resources 列与 Update 动词；域包 `internal/domain/data/pubsub|bucketstore/`，Repo 接口随聚合，ADR-0075 律）；**机制层归一** = `internal/application/dataservices` 单卫星包 + family descriptor 注册表（域聚合 Repo/模板包/凭证连接方言/备份能力/配额/事件码族；**注册表本体下沉 domain**——backups/dataservices 两卫星与 gRPC handler 合法消费，规避卫星间硬边〔红队 B-AT-01〕）——受管域「一个通用 reconciler + N 个 Describe()」（ADR-0004）的用户域对称形态，满足 ADR-0087 机制原语三判据。**环表三条目（红队 B-击二翻案，取代初版「单环+家族步 recover」）**：`database`（保留名，step 改调卫星分族步）/`pubsub`/`bucketstore` 三条，环表 10→12——机制单源+故障域隔离+**ring dead 教义原样执法**（loop.go panic→ring dead 不收窄）三者全保、每族一环=每族一写者；初版单环案被否（假二分：只省一个 ticker，却把家族级 bug 挡在 health 面外）。**既有 databases 卫星迁入 descriptor 是 B2e 机制统一步，验收 = 明示漂移清单下的稳态等价**（不宣称零漂移——红队 C-AT-02；漂移清单：memo 第四段/环 step 指向/卫星包名，环名与 health 面不变）。CRUD 三 proto 服务面不变，gRPC 实现共享通用 handler core（descriptor 参数化，manageds 先例）。**三轨一基**（词条随 B1 入册）：数据服务与 App/受管域共享 L1 公共运行保障（Workload/Runtime.Ensure/材料纪律/Generation 内容等价/卷网观测/稳态看门狗；spec 对照 drift 维持 ADR-0029 豁免——红队 B-AT-09），仅不取 App 编排面（Deployment 状态机/Revision/Strategy/Admission——行即期望态，per-row Generation 原位收敛）。
2. **三轴与双 runtime**：NamespaceRef 增 `.PubSub`/`.BucketStore`（ADR-0025 分立律——拒塞 `.Database` 字段）；swarm label/载体名（`fleetly-pub-<name>-<id>`/`fleetly-bkt-<name>-<id>`，ADR-0092 双段律）/DNS（`pub-<id>`/`bkt-<id>`，engineports 铸名族下沉同源）；**swarm 与 k3s 翻译同批落**（databaseNamePrefix 同源公式先例，metricsquery 双臂正则连坐扩）。挂全部活跃项目网（fail-closed 零网拒建）+EgressSubset+卷钉住+挂卷 stop-first 既有律全适用。
3. **模板包三立**：pubtemplate/buckettemplate 新包 + enginetemplate 共享内核（VersionSpec/Knob/Backup·Restore·Rotate·Apply Spec/MintPassword/pinnedRef/validatePassword）；Template 接口按家族分叉——**连接材料渲染取代 URL 假设**（Kafka=bootstrap+SASL 无 URL 方言；数据库家族保留 URL 单真源不动）；Secret 值 = 家族方言串，渲染器/回读器同源（写读同源律）。
4. **凭证**：`pubsub:<name>`（nats=平台合成用户住 nats-server.conf——声明式轮换 redis 同款；kafka=SASL admin 用户住 listener 配置——轮换=滚动，**轮换方言 B6 评估倾向挂账**）；`bucketstore:<name>`（silo root AK/SK——复合凭证 k=v 串，轮换=滚动）。**silo 单用户模式取舍（评审 F-07）**：root 全权限超管是 zot per-Project 凭证域先例（ADR-0056）的倒退；v1 接受论证 = 单 Project 独占实例（zot 是多 Project 共享）+ per-App service account（silo 是 MinIO 系 fork，IAM 策略面可支撑）挂 B5 live 定案。MintPassword 同源；值永不回显。Browse 面对两家族 fail-closed 拒（ADR-0051 注册表外语官既有拒；轻量 web 工具缺——kafka-ui Java 重/nats 无，挂账独立评估）。
5. **连接注入**：App Spec `pubsub_refs`/`bucketstore_refs`（ProcessSpec **字段 19/20**——17/18 已被 config_mounts/restart_seq 占用）→ `FLEETLY_PUB_<NAME>_{URL|BOOTSTRAP}/HOST/PORT/USER/PASSWORD`（NAME=引用名 UPPER_SNAKE；nats 出 URL、kafka 出 BOOTSTRAP+MECHANISM）与 `FLEETLY_BKT_<NAME>_ENDPOINT/ACCESS_KEY/SECRET_KEY`；**明文 env 承载凭证 = ADR-0014 附录 A.2 追认范围显式扩至本两族 refs**（PUB_PASSWORD/BKT_SECRET_KEY 是长效凭证、暴露面大于可原地轮换的 DB 密码——「同信任域随载体 spec env 下发」论证在此落纸，不默示继承 database_refs）；`InjectDatabaseEnv` 泛化为 refs 注入帮手；compose label `fleetly.pubsubs`/`fleetly.bucketstores` 走 external 声明律+**intake 白名单显式入册**+受理告警建议（**zeabur B5.5 挂账收口**）；`secret_refs` 文件注入通道复用。
6. **统一转储契约（备份/还原/迁移，2026-11-05 用户裁决）**：备份、还原、迁移 = 同一原语（实例数据面 dump→load）的三种编排；引擎差异收进模板契约（Dump/Load Spec、ArtifactShape=单流|对象集、RestoreCompat 版本矩阵、DataCapabilities 能力位），机制层（backups 卫星）跨族单源（family descriptor 归一）。**产物 = manifest 锚定的对象集**（单流引擎 1 成员、NATS 逐流 `.tgz`；verify/Download/修剪全 manifest 驱动；无兼容层前提直上 manifest 形不迁旧键；Platform Backup 捎带两层分立不动〔ADR-0039〕；manifest 机制随 B4 落地全族换形+e2e 重钉）。**还原 = restore plan**（受理 RestoreCompat〔源=backups 行 engine_version，ADR-0094 决策 5〕+ preseed 前置〔Generation==0+卷钉控制面〕；三入口同 plan：`--restore-from-backup`/升级正典①/实例克隆）。**迁移铁律**：数据面迁移一律 dump→load（ObjectStore 断点可重放可验证）、载体面迁移一律卷搬运（drain+repin，限同 Runtime）——两径不混用；版本迁移=ADR-0094 正典、载体迁移=runbook/ADR-0052 语义。**能力位诚实推论：backup=false ⇒ migrate=false**（kafka v1 major 升级=新空实例或外部工具，目录/文案披露；silo 同挂账）。挂账：跨 Project 克隆、post-load 数据断言（e2e 域）、nats 产物形态 B4b live 定案（**natsio/**nats-box 钉版——synadia/ 命名空间停更 5+ 年不可用；**memory storage 流不可快照→受理拒**，红队 C-AT-06）。**物理约束三条（红队 A2/A3 立法）**：①NATS 不可流式——工具容器逐成员串行「落盘→Put→删本地」，manager 磁盘峰值=最大单成员；②对象集**逐成员独立预算**（BackupTimeout 15m 整集单预算=大体量永久失败循环）；③**manifest 最后写**（全成员成功才落行）+失败显式删已 Put 成员+List 孤儿对账；④schedulePass 按 DataCapabilities.backup 过滤——无备份引擎不铸行、受理禁配 interval（「33h 11.4 万行」事故防复发）。
7. **引擎选型**：nats=`nats:<ver>-alpine`（scratch 默认变体无 shell 不可 exec 探针；alpine 带 busybox wget 打 8222 `/healthz`——「不依赖 nc 假设」律满足；JetStream `-js -sd /data`）；kafka=`apache/kafka:<ver>`（KRaft 缺省、`KAFKA_*` env→properties 翻译、单节点 combined、探针 `kafka-broker-api-versions`——**探针/listener 分面 B6 live 定案**：9092 开 SASL 后无凭证探针被拒，加内部明文 listener 专供探针；SASL 机制 **PLAIN vs SCRAM-SHA-256 二选一 B6 live 定案、倾向 SCRAM**〔免证书且凭证不过明文，KRaft 3.5+ 住元数据〕，评审 F-14；传输 PLAINTEXT 内网口径——zot 明文同文化；bitnami 变动荡排除）；silo=`pgsty/silo`（e2e 既有镜像转正，正式选型 B5 落定；RustFS 维持 ADR-0042 挂账不吸收）；**redpanda=`redpandadata/redpanda` v26.x（Kafka 协议族第三方实现，2026-11-05 用户裁决入值域）**——**方言族机制**：engine=实现名（不造合成名）、方言族=连接/注入形态复用单元（redpandaTemplate 嵌 kafka 方言基座只覆盖镜像/配置/探针/版本/knob，pgvector:postgres 先例）、目录加 `dialect` 字段同族互示兼容（客户端零改动切换）；native 无 JVM 堆、**生产形态=平台完整渲染配置**（dev-container 是官方明示非生产预设——dev 默认逐项收编，`auto_create_topics=false` 强制渲染，红队 A4）、**探针/listener 分面同 kafka**（SASL 启用后 rpk 无凭证被拒——admin API 9644/带凭证 rpk/内部明文 listener 三选一 B6b 定案，红队 A4 撤销「无分面问题」断言）、**方言基座继承律：Dump/Load/Apply/Rotate Spec 各自覆盖或显式声明不继承**（redpanda 镜像无 kafka-configs.sh）；备份同 kafka 挂账（backup=false⇒migrate=false）；**BSL 1.1 许可披露**（含 Change Date 各版发布起 4 年逐版转 Apache 2.0——披露完整化）与 **silo AGPLv3**（MinIO fork 继承）同入**目录 license_note 全引擎化**（红队 C-AT-06：AGPL 网络条款对「平台替用户跑」形态的审视比 BSL 用例限制更敏感），托管合规裁定归运营方、代码面不设限。未来 valkey/mariadb/ferretdb 等兼容实现同机制承接。首批矩阵与 Default 见 ADR-0094 决策 7。
8. **API/CLI/Console/守卫**：PubSubsService/BucketStoresService（Create/Get/Resolve/List/Delete/Update/RotatePassword/Backup 族按 capabilities 裁剪；ADR-0092 Resolve name 寻址同律）；五守卫+authz 词表 `pubsubs`/`bucketstores` 资源；写类分桶（CRUD=DECLARATION，Trigger/Rotate=ACTION）；事件只增（`pubsub.*`/`bucket_store.*` 各四——created/updated/deleted/credentials_rotated，与 database.credentials_rotated 先例对齐，评审 F-17）；errcode 复用既有 + E_SETTINGS_APPLY_FAILED（ADR-0095）。CLI 组 `fleetly pubsubs`/`fleetly buckets`；Console 姐妹页（ListPage+详情英雄卡 tab 同形态，一页一壳律）；skills `pubsub-provision`/`bucketstore-provision` 随批。**配额**：pubsubs 8、bucket_stores 4（databases 16 不动）。
9. **平台自宿 ObjectStore 显式分立**：本程序是用户域数据服务线；ADR-0042 决策 3 RustFS 受管自宿（系统域备份目标自宿）维持独立挂账，互不吸收。

## 后果

- 三家族机制单源化（enginetemplate 内核+目录+Update 双车道），第四家族（若有）复制成本 = 一个模板包+一个环+一组 CRUD。
- kafka 无数据备份是诚实取舍：目录 capabilities 让用户创建前可见，不静默。
- FLEETLY_* env 族扩两支：App 连接面从 DB 单支扩为三支，compose/intake/文档面同批连坐。
- 环表 10→12（dataservices 单卫星包 + database/pubsub/bucketstore 三条目，step 同源调 descriptor）：机制单源+故障域隔离+ring dead 执法三保；第四家族（若有）接入成本 = 一个模板包 + 一个 descriptor entry + 一组 CRUD + 一条环表行（产品面仍是一个 B5 级整批 ≈3–5k LOC——红队 C-AT-04 注价）。

10. **子资源管理面（B8，2026-11-05 用户终裁随批进）**：Topic（kafka 协议族）/Stream（nats）/Bucket（bucket store）为**声明行 + admin 工具容器收敛**（`kafka-topics.sh`/`rpk topic`/`nats stream`/S3 API，按 engine 方言；对齐 ADR-0081/0082 严格声明式）：收敛对照行期望态 ensure（存在+配置匹配否则创建/更新）；删除=声明式 GC（Topic/Stream 删除即数据删除——wide 档确认+不挂引用断言）；配置可变面走 Update 双档同律；配额 per 实例；事件码只增（`topic.*`/`stream.*`/`bucket.*`）；Topic/Stream 词条随 B1 入册（ADR-0093 决策 4 翻案）。机制细节见 design §4.7。
