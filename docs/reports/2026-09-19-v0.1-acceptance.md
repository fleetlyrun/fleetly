1. **M2（delivery §2.6 / §2.2 release 轨道）**：真 VPS dogfooding、VPS 验证脚本化、TLS/ACME 对 LE production 真路径、资源基线趋势（nightly 已有采样 job，本报告为对照基线）。

3. **已知边界（本阶段记录，非阻断）**：
   - git push 入口的 compose 须引用既有镜像——服务端从 bare 仓库取 compose 落临时目录，`build.context` 相对路径不可达（源码构建走 CLI/API deploy 入口，构建管线已由 conformance 实证）；git 源物化评估列 v0.2。
   - 平台依赖镜像（traefik/alpine/moby/buildkit）不自动拉取（T2.15 已知边界），安装后首启在线拉取；离线环境需预置。
   - Pebble 镜像实际可用名为 `ghcr.io/letsencrypt/pebble`（Docker Hub `letsencrypt/pebble` 已不可拉）；其 ACME 链根为启动期随机生成且无 HTTP 取根端点，ca_pool 取镜像内 minica 根（仅信任 pebble 监听证书），旅程对 443 证书的断言采用「服务链 ≡ 平台账签发链」等同性口径。
   - 构建一次性瞬态：buildkit/containerd 写锁 `ref locked` 可致单次构建 `E_BUILD_FAILED`（校准 run4 记录 1/5；重跑即成）。v0.1 由用户/API 层重试，与「发布失败不自动重试」口径同构。
   - ACME HTTP-01 的 Traefik 应用生效确认：`internal/ingress/acme.go` Present 在 awaitServed（fetch 确认）后新增 `awaitChallengePathLive` 主动探测（本阶段修复，见 §7）。

## 7. 本阶段产品修复（Go 改动单列）

- **`internal/ingress/acme.go`**：旅程暴露「挑战路由已下发（fetch）≠ Traefik 已应用（apply）」竞态——CA 校验请求先于 Traefik apply 到达时挑战路径 404、authz 直接作废（lego 不重试单一 challenge；复现于 5 次旅程中的 2 次）。修复 = Present 在 awaitServed 后新增 `awaitChallengePathLive`：主动探测「经 Traefik 的挑战路径」应答 = keyAuth 才放行（预算 6s，超时保持原「不阻塞签发」口径）。修复后旅程连续全绿（§2），`internal/ingress` 包测试通过。
