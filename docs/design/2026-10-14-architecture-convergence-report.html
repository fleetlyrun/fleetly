命名定稿：导出面零后缀

  • ▪ 聚合仓储：project.Repo / deployment.Repo（包名限定 + 裸 Repo，37 同构）；实现不导出，wire.Bind 绑定
  • ▪ 引擎：engine.Engine 唯一导出协调类型（冻结词条）
  • ▪ 九域内核不导出：type tasks struct type execs struct…（复数普通名词掌管状态；同包白盒测试直接构造）
  • ▪ 消费侧接口不导出：type gitClient interface（accept interfaces 惯用法）
  • ▪ gRPC 35 个 XxxService 维持（proto 生成契约强制）
  • ▪ 检验标准：导出类型 grep 后缀近零；方法论只存在于四个目录名

三条 ADR 例外（显式记录，不伪装合规）

  • ① 贫血聚合 + 状态机集中在 writes kernel/engine（单写者收敛是第一设计决策）
  • ② admin 离线写绕过 kernel（控制面已停的维护语义）
  • ③ 读写分离律：interfaces 可直读 domain.Repo；一切写必经 application

自审修正的 6 处违反（v3→v4 变更）

① apperr 引 genproto → 信封纯化入 domain，status 构建器移 interfaces；② material 含文件 I/O → 纯密码学留 domain，keyring 装载入 infrastructure；③ "零豁免"言过其实 → 读写分离律立法；④ capability 混装 → 纯类型+纯函数纪律守卫；⑤ anchor/writes 留 application 是保守 → 下沉 domain（writes 自带 Runner 端口）；⑥ domain 平铺 37 聚合 → 按八限界上下文嵌套（对齐 proto 服务族）。

三、P0 案卷（安全/并发/正确性，全部主会话复核实证）

  • S1 StreamExecSession 无行级授权 + 会话 ID 单调可枚举（exec.go:173-190 / engine exec.go:217）→ 跨队容器命令注入
  • S2 events 三读面零 Team 过滤、outbox 无 team 列（contexts.go:250-370）→ 跨队事件流泄漏（刀 1 终态修复，P0 先做最小修）
  • K1 未附着 exec 会话零回收（timer 只在 AttachClient 装）→ 8 次锁死 team 配额；exec.go 全文件零测试
  • K2 deliverRelayFrame 非阻塞 send 无 closed 复查 ⇄ finishSession close(s.out) → panic 杀整条节点中继
  • E0 E_INTERNAL 三面割裂（error_id 只在 REST；gRPC/CLI 原样泄 SQL）
  • job 方言 白名单旁路静默丢键 + command 双重逃逸（intake.go:448,499-503）——同语义三面两口径
  • Q1 managedStep 每秒无条件 UPDATE last_seen_at（空闲 WAL churn）；Q2 CLI 按名查重只拉首页 50 条（>50 误判不存在重复创建）
  • k3s Watch 静默失败族 / 无 recover / 退避不看 ctx（swarm 已修同族）
  • state 写路径 INSERT 无唯一冲突归一（裸 E_INTERNAL）/ backup 终态无 CAS / run 手抄 task 终态字面量
  • api_base SSRF 私网/环回不拒 + 上游 message 回显
