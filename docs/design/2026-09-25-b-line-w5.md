## 1. 自动扩缩（Autoscaling）

### 1.1 策略模型

- **作用域**：per app × per compose service（`state` 新表 `scaling_policies`：app_id/service/min/max/target_cpu_pct/target_mem_pct/cooldown_seconds/created_at/updated_at；服务级单策略）。
- **API**：AppsService 增 GetScalingPolicy/SetScalingPolicy/RemoveScalingPolicy（deploy/admin 门——资源面写语义；机具令牌 admin 等价照旧）。CLI `fleetly apps scaling <app>/<service> --min --max --cpu 60 --mem 70 --cooldown 180` + `scaling show/rm`。Console：App 详情增 Scaling 卡（admin 可写）。
- **约束**：min ≥1、max ≤ 16（swarm 单服务上限口径，防误配爆炸）；target ∈ [20,90]%；cooldown ∈ [60,3600]s 缺省 180。

### 1.2 评估器（engine 内 duty）

- 挂 engine 收敛拍尾部（与 dutyBackupScheduling 同族）：对**有策略且 metrics.mode=on 且服务 running** 的 service 求值；metrics off 时策略休眠（事件 `scaling.dormant` 一次性披露，不重复发）。
- **数据源**：VM `/api/v1/query` 按 service 聚合 cadvisor 指标：CPU=`sum(rate(container_cpu_usage_seconds{container_label_com_docker_swarm_service_name="<svc>"}[2m])) / <期望副本×限额核数>`、内存=`avg(container_memory_working_set{...}) / <限额字节>`。查不到序列=**不动作**（诚实无数据不扩缩，事件披露一次）。
- **判据**：两维度任一超 target+10%（扩）或低于 target−30%（缩）→ 拟调整副本 = ceil(当前×target/实测) 夹 [min,max]；变化为 0 不动作。
- **动作**：经引擎自身副本写通道更新期望副本（**写进 app 派生期望态而非 compose spec**——漂移对账以「平台自己写的运行期副本」为期望，外部 `docker service scale` 的漂移判据不因此误报；具体落点=spec 的运行期副本覆盖层，实现票读 `internal/engine` 对账与 F11 护栏后定形并测试钉死）。冷却窗内不重复动作；事件 `scaling.adjusted`（metadata：维度/前后副本/实测水位）+ 审计 `scaling.policy_changed`。
- **护栏**：stateful（有卷）服务默认**只扩不缩**（数据安全纪律，与 E4 库不自动缩同口径——策略可显式 `--allow-shrink` 破例？**不**——首发一律只扩不缩，挂账）。

## 2. 告警（vmalert 捆绑）

### 2.1 栈形态

- `alerts.mode` ∈ unset|on（platform_settings，同 metrics.mode 形态；**前置门=metrics.mode=on**——vmalert 没有 datasource 无意义，off 时设置拒绝 409 带指引）。
- **vmalert 服务**（metrics 栈第四组件，opt-in 豁免预算）：镜像 `victoriametrics/vmalert`（实现时点解析钉 digest，台账登记）；host 网络回环拓扑与三件套同族；`-datasource.url=http://127.0.0.1:8428`、`-remoteRead.url` 同、`-notifier.url=http://<advertise>:<网关端口>/internal/alerts`、`-rule=/etc/vmalert/rules/*.yaml`（swarm config 挂载，scrape config 同款分发）、`-evaluationInterval=30s`。
- 镜像台账登记+e2e 同 digest 拉取（三件套同款）。

### 2.2 规则模型与 API

- `state` 新表 `alert_rules`：id/name（project 内唯一?**平台级**——告警面向平台管理员，与 notifications 端点同域）/expr（PromQL，buf 校验非空+长度）/for_duration/labels(JSON，含 severity)/channels(JSON，通知端点 id 集)/created_at。
- `AlertingService`（平台管理员门）：CreateAlertRule/ListAlertRules/UpdateAlertRule/DeleteAlertRule/SetAlertsMode/GetAlertsStatus（vmalert 服务态+规则数）+ **TestAlertRule**（单次求值试跑——datasource instant query 直接执行 expr 返回样本，用户写规则时的即时校验面）。
- **渲染**：规则 → Prometheus rule 文件（groups 单组；`for` 映射 for_duration；annotation 携带 channels/severity/name）→ swarm config `fleetly-vmalert-rules-<sha8>`（内容寻址，scrape config 同款增删换）→ vmalert 服务更新。

### 2.3 通知接收器（平台内建）

- 网关原生 handler `POST /internal/alerts`（Alertmanager v2 webhook 载荷：alerts[]，status firing/resolved、labels、annotations、startsAt/endsAt）——**认证**：ingress token 同款 Bearer（vmalert `-notifier.basicAuthUsername/Password` 传平台生成凭据，token file 复用）。
- 映射：firing → 既有 notify 投递（按 annotations.channels 解析端点 id 集，缺省投全部端点；severity 进文案）；**resolved → 恢复通知**（文案 `RESOLVED` 前缀——vmalert 原生带 resolved 语义，正好补上 OO 评估里 OpenObserve 缺的那块）。去抖/退避沿 notify 既有投递预算；**告警投递不产生事件**（防回环红线沿用——vmalert 不经事件流）。
- Console：告警规则管理页（平台管理员；expr 编辑+Test 即时求值+通道绑定勾选）+ alerts.mode 开关；CLI `fleetly alerts rules ls/create/rm/test` + `alerts mode`。

## 3. 通配证书 DNS-01

### 3.1 服务商插件

- `internal/acmedns` 包：接口 `Provider`（Present(ctx, fqdn, token/keyauth)/CleanUp）+ 注册表；实现 **dnspod**（API token：`id,token` 形态，`api.dnspod.cn` Domain.Record.Create/Delete，TXT `_acme-challenge.<domain>`）与 **cloudflare**（API Token 最小权限 Zone.DNS Edit，`api.cloudflare.com/client/v4`）。零第三方 SDK——两家的 REST 都够简单（HTTP+JSON，标准库+既有 HTTP client 形态）。
- 凭证：platform_settings `acme.dns.{provider,credentials_cipher…}`（S3 设置同款 envelope 加密；TestDnsProvider 探针 RPC：列域名/建删测试 TXT 验证）。

### 3.2 签发链

- 设置 `acme.wildcard=true`（platform_settings，需 DNS 凭据就绪——设置校验联动）→ 平台证书期望域名集变 `[*.base_domain, console/ctrl/registry.<base>]`（SAN 一张；needsRenewal 域名集变化即重签的既有判据直接复用）→ ACME 走 DNS-01（challenge 用插件 Present/CleanUp）。
- 关闭开关=回三 SAN HTTP-01 形态（域名集再变再重签，既有判据复用）。**app 域名路由零变化**：wildcard 就位后 app 证书保障路径=通配优先（app 不再需要 per-app 证书即有 TLS——per-app HTTP-01 证书签发保留给「app 绑定非 base_domain 的自定义域名」场景）。
- 预拉台账登记 vmalert 镜像行；staging 真机验 DNSPod 路径。

## 5. 挂账

自定义 PromQL 扩缩触发；有卷服务缩容（首发只扩不缩）；vmalert 规则分组/回放（replay）高级面；DNS-01 更多服务商（Aliyun/GoDaddy 等）；告警静默窗管理面（vmalert 原生 for 承载，平台静默 UI 挂账）；OpenObserve 观测高级层（V3W5-E1 重评三条件）。
