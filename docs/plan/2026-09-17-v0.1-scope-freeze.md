## 1. 裁决（本清单新增的口径，不是复述）

| # | 裁决 | 理由 |
|---|---|---|
| FZ-1 | **「自动连接串」后置 v0.2**：v0.1 第 4 项 env/密钥交付 = 加密存储 + 注入 + 三层合并，无连接串生成（v0.1 无数据服务可连；连接串随 v0.2 数据库模板落地，以 `source=system` 平台 env 形态注入） | 架构 §4.2 第 4 项的遗留歧义；v0.1 不留空机制 |
| FZ-2 | **退化信封口径**：无 ErrorResponse detail 的错误（框架/传输层）经 gateway 输出 `code:""` + message 保底的通用信封，HTTP 状态由 grpc code 机械映射——不发明清单外码、不挪用既有码语义 | 阶段 3 遗留①裁决：接受实现取舍，冻为 v0.1 口径 |
| FZ-3 | **未定 HTTP 映射的 15 个错误码冻结如下表缺省值**（文档显式给定的 9 个维持：`E_STATE_VERSION_CONFLICT`=409、`E_LABEL_RESERVED`=422、`E_DOMAIN_CONFLICT`=409、`E_PLACEMENT_MOVE_REQUIRES_ACK`=409、`E_VOLUME_NODE_MISMATCH`=409、`E_PLACEMENT_LABEL_CONFLICT`=422、`E_PLACEMENT_NODE_INVALID`=422、`E_PLACEMENT_NODE_NOT_FOUND`=422、`E_EVENT_CURSOR_EXPIRED`=410） | 阶段 3 遗留②裁决；调整任一映射 = 契约变更，须评审 |
| FZ-4 | **cron 超时事件命名 `cron.timed_out`**（与 `cron.skipped` 过去分词风格一致；按只增流程随后续 cron 实现入注册表，当前注册表 35 事件不含它属预期） | 阶段 3 遗留③裁决；架构 §4.3「超时→事件」的命名补全 |
| FZ-5 | **校验违规（protovalidate）信封**：`code:""`（InvalidArgument）+ 违规字段路径进 `context`——不新增 `E_REQUEST_INVALID` 类通用码；v0.1 用户可见的同步校验错误集中在 compose 解析层（`E_COMPOSE_*`） | 与 FZ-2 同源：清单外不造码 |

### FZ-3 缺省 HTTP 映射表（15 码）

| 码 | HTTP | 语义依据 |
|---|---|---|
| E_COMPOSE_UNSUPPORTED / E_COMPOSE_MANAGED_FIELD / E_COMPOSE_UNSAFE_STRATEGY | 400 | 同步校验拒绝（apply 前失败，发布专项 §2.5 场景 1） |
| E_CAPABILITY_REQUIRES_MULTI_NODE | 400 | 单节点误用多节点操作（放置 §2.9） |
| E_PLACEMENT_NODE_UNAVAILABLE / E_PLACEMENT_NODE_GONE / E_PLACEMENT_NO_ELIGIBLE_NODE | 409 | 部署前哨阻塞（快速失败，放置 §2.5） |
| E_ROLLBACK_NO_TARGET | 409 | 目标越界（发布专项 §2.4） |
| E_BACKUP_KEY_MISSING | 500 | 恢复流程系统错误（状态模型 §2.7） |
| E_BUILD_FAILED / E_IMAGE_PULL_FAILED / E_IMAGE_UNAVAILABLE / E_SCHEDULER_PENDING_TIMEOUT / E_TASK_START_FAILED / E_HEALTH_TIMEOUT / E_OBSERVE_CRASH_LOOP / E_OBSERVE_UNHEALTHY / E_DEPLOY_INTERRUPTED / E_DEPLOY_POST_WINDOW_UNSTABLE / E_DEPLOY_DOWNTIME_FAILED / E_ROLLBACK_FAILED / E_RUNTIME_UNAVAILABLE | 503（E_RUNTIME_UNAVAILABLE）/ 500（其余） | 管线执行类；注意「部署失败是资源终态而非 HTTP 错误」——这些码主要出现在 deployment 资源与事件流，HTTP 面仅在同步触发（如 preflight 立即失败）时呈现 |

## 2. 三专项 v0.1 实现切面（冻结）

## 3. 范围外提醒（防蔓延）

- v0.1 只做单节点；多节点语义（场景 15/16、HA 边界、zot）一律 v0.2。
- 注册表码集 = 设计文档全量（实现面按需消费）；新增码走「只增 + 评审」。
- 本清单与任务分解冲突时，以本清单为准（更新须同步任务分解）。
