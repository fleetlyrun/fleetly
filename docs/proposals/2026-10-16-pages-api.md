# fleetly Pages API 提案（静态站点托管产品面，2026-10-16）

> 状态：**搁置**（2026-10-17 用户裁决：暂时搁置，等有需求了再实施；届时以本文件为裁决载体——§0 总表逐案给裁决，§6 开放问题逐条给答；裁决后实施批各自开 ADR 并携带守卫任务，按 2026-10-03 提案集同款纪律）。
> 核心问题：**Pages 是否可以依赖 Functions API 构建**。结论先行：**机制上可以、战略上不必——v1 推荐 App 构建链特化（甲案，§2.1），Functions 依赖（乙案，§2.2）的真增量全部落在 Functions Phase 2 缩零成本面，届时以干净换轨路径衔接；独立静态服务实体（丙案，§2.3）否决。**
> 载荷澄清：Pages 指 Cloudflare Pages / Netlify / Vercel / GitHub Pages 一族的**静态站点托管产品面**——git/上传接入 → 构建 → 生产 URL → 分支预览部署 → 服务语义（redirects/headers/SPA 回退）。是内容形状的产品化，不是新计算模型；后端动态面（SSR/API routes）不是本提案范围（那是 Function/App 的皮，Functions 设计 §13 torchwood 同款口径）。
> 词汇遵守 CONTEXT.md：`site` 在 App 词条 _Avoid_ 表（竞品域内混用禁，CONTEXT.md:49）——拟议产品线命名不可用，行/实体命名随 §6.1/§6.2 裁决；「Pages」与 console 页面泛称有语义碰撞风险（ADR-0059 在册页面名词先例），若裁决通过走 ADR-0007 显式修订通道入册词条。裁决前本文件为提案语境，非域内混用。
> 关联：`docs/design/2026-10-16-functions-api.md`（三轴 deletion test → 词汇 ADR 先行 → 设计稿程序；本提案沿用其 §2.1 轴表口径）；CONTEXT.md App/Source/Build/Builder/GitHook 词条；ADR-0032（builder 家族 railpack+static）、ADR-0019（控制面构建 + zot）、ADR-0072（push 合并所有权）、ADR-0073（GitHub App 材料）、ADR-0059（页面命名）、ADR-0064（内容寻址）、ADR-0070（名基可读 id）。

## 1. 背景：地基核查（2026-10-16 全仓探明）

核心发现：**Pages 的主体价值链在 App 构建链上今天已完整存在**——

| Pages 需要 | fleetly 现成面 | 佐证 |
|---|---|---|
| 静态目录 → 可路由镜像 | **static builder 已在册**：上传上下文的产物子目录 COPY 进钉版 `caddy:2.11-alpine`，注入生成 Caddyfile（:8080 + SPA `try_files {path} /index.html` 回退 + file_server） | `internal/infrastructure/providers/builders/static.go`；ADR-0032；CONTEXT.md Builder 词条 |
| 上传接入 | tar 流式上传（单次 512MiB、项目 4GiB）、内容寻址落盘跨项目去重、tar-slip 防护；UploadSource = Source 三形态之一 | `internal/infrastructure/upload/store.go`；`proto/fleetly/spec/v1/spec.proto` Source |
| git 接入 + 自动部署 | GitHook HMAC webhook：push → 分支/watchPaths/`[skip deploy]` 过滤 → SubmitSpec push 合并 → Build → 新 Revision → 部署（返回 DeploymentId）；RefreshGitHook 控制面主动拉取的一等孪生 | `internal/interfaces/grpc/fleetlygrpc/webhook.go`；ADR-0072 |
| 私有仓材料 | GitHub App installation token 现铸 clone（Project/Global 双作用域） | ADR-0073 |
| 镜像受管推拉 | zot 受管 registry，per-Project 推送凭证，Revision 冻结 digest；构建走 docker daemon 内嵌 buildkit | `providers/zot`、`providers/builders/daemon.go`；ADR-0019 |
| 公网路由 | Route 行（host/path/app/process/port/protocol/tls），TLS auto 逐 host 换发 | `proto/fleetly/proxy/v1/proxy.proto` |
| 构建日志 | Build Log 帧流（live 缓冲 + Logging 持久，出口脱敏） | CONTEXT.md Build Log 词条；ADR-0040 |

真缺口（= 本提案的工作量所在）：

1. **分支预览部署**（灵魂件）：GitHook 现为单分支过滤；无短命预览环境环、无 PR 事件解析、无自动回收；
2. **产品面**：Pages 动词组/Console 页/URL 派生约定——`<name>.<base_domain>` 类派生 host 无现成面（Route host 手给；sslip 拼装在 templates 有先例）；
3. **服务语义**：SPA 回退已有；`_redirects`/`_headers`/自定义 404/immutable cache-control 无；
4. **闲置成本**：每站点一个常驻 caddy 容器，无缩零。

## 2. 核心裁决：是否依赖 Functions API（design-it-twice 三案）

### 2.1 甲案（推荐 v1）：App 构建链特化——Pages 是 App 的产品化糖

机制全复用：**Pages 站点（提案语境指称，§6.2 定名）= CreateApp(source = git|upload × builder = static) + Route +（git 形态）GitHook**；Pages 产品面 = 预设糖（CLI `fleetly pages …` 动词组、Console 页、URL 派生约定、服务语义文件）。

- **零新执行实体、零新引擎面、今天可开工**——对照乙案：Functions 连 `proto/fleetly/delivery/v1/functions.proto` 都尚不存在（Phase 1 未始，设计文档 2026-10-16 才定稿 v2）。
- **Route 行面是净胜而非妥协**：逐路由 Console 集成、逐路由日志/事件面现成——Functions 设计自己诚实记录了合成路由的能力天花板（其 §15.3），App 路线没有这个天花板。
- 诚实代价：①每站点常驻一 caddy 容器——**Coolify 静态站正是同款形态**（自托管界先例：每站一 nginx/caddy 容器），caddy 空载足迹 ~10MiB 级，自托管密度下是常态而非缺陷；②站点枚举/预览策略需要行面归宿（§6.1 开放问题，P1 可零行先行）；③换镜像/构建参数走 App Deploy 全量替换面，无 Pages 专属 overlay（ADR-0072 所有权分裂原样适用：git 挂钩后材料归 push）。

### 2.2 乙案：Functions 依赖——机制可行，v1 三重阻塞

1. **Functions 未开工**：依赖一个没有代码的产品线；
2. **v1 源 = image 直投**：upload/Build 源被设计文档明确推迟到 Functions Phase 2 首项（Revision 就绪门迷你状态机）——Pages 恰好最需要构建源，依赖乙案等于排队在 Functions Phase 2 之后；
3. **min_replicas ≥ 1（v1 常驻）**：与 App 链零成本差——依赖在 v1 不买任何东西（乙案 v1 落地形态恰好退化成甲案：static builder 产出的 caddy 镜像经 DeployFunction 直投，多绕一层 Function 行换少一层 Route 行）。

乙案的真增量全部在 Functions Phase 2：**缩零+唤醒**（大量闲置站点零载体成本——Pages 是唤醒面最典型的负载画像）、`functions.base_domain` 派生 host、区间自动伸缩。**结论：乙案不是 v1 依赖，是 Phase 2 成本面升级路径（P5）**——站点从 App 换轨 Function，URL/材料/构建链全部不动，换的只是 Workload 投影宿主；迁移语义（Route 行退场换合成路由、Revision 史衔接）届时显式 ADR。附带红利：Pages 站点全 public，天然落 Functions Phase 2 唤醒方向甲候选（公网受管面唤醒）——**Pages 可成唤醒组件的第一个真实消费者**，不碰 private 唤醒开放难题。

### 2.3 丙案：独立 Pages 实体 + 共享静态服务组件（Cloudflare 架构）

对象存储资产面 + 多租户共享静态服务 + 缓存层。否决理由：①平台无通用对象存储面（ObjectStore Capability 只服务备份，ADR-0020/0042）；②引入第二条服务路径，违反「数据面 = 普通 Workload，平台不定义第二协议」简洁律（Functions 设计同款纪律）；③自托管单集群密度用不上共享面摊薄（Cloudflare 是多租户边缘云才必须共享）；④预览部署走短命容器比走共享面资产 GC 简单一个量级。**触发重评**：单安装数百站点密度实锤、或边缘缓存/全球加速需求立案。

### 2.4 裁决推荐

**甲（v1 产品面）→ P2 预览环（甲上叠加）→ Phase 2 视闲置成本实锤决定 P5 换轨。**对 Functions 的关系定为：**非依赖、同族**——两条交付面产品线共享 Spec/Revision/Route/Build/zot 地基但互不排队、互不塑造对方形状（Functions 设计裁决基础 2 的对称适用）。

## 3. deletion test：Pages 不是第四执行实体

| 轴 | Pages 站点 | App | Function | Task |
|---|---|---|---|---|
| 激活模型 | 声明常驻（**与 App 同格**） | 声明拓扑常驻，副本 ≥1 | 请求驱动，可缩零唤醒 | 创建/调度驱动，TTL 或租约收口 |
| 计量轴 | per-runtime（**与 App 同格**） | per-runtime（实例×时间） | per-invocation | per-Run |
| 粒度 | 静态目录（**内容形状**） | 多 Process 声明拓扑 | 单代码入口 | 镜像直投单形 |

判据：**Pages 是内容形状（静态资产），不是激活形状**——三轴上与 App 完全同格，不产生 App/Function/Task 覆盖不了的行为；其产品价值 = 预设 + 预览策略 + UX + 服务语义（§1 缺口 2/3/4），全是 App 之上的薄层。与 Agents 提案对照：agents 过 deletion test 是因为交互驱动是三执行产品都不承载的真空缺；pages 不过——§1 地基核查证明执行面已被 App 链覆盖。**执行宿主不立实体**；预览策略等持久配置的行面归宿见 §6.1。审查义务同款：每期复盘重跑本节。

## 4. P1：Pages v1 产品面（甲案落地形态）

- CLI 动词组（双形态 golden；旗标前置铁律入组内自查）：

```
fleetly pages create <name> --git URL --branch B | --upload DIR   # = apps create 预设：builder=static + Route(host 派生)
                                                                   #   + (git 形态) GitHook；--wait 收敛
fleetly pages deploy <name> [--branch B]                           # git 挂钩 = RefreshGitHook 语义(拉取即部署)；
                                                                   #   upload 形态 = 新上传 + Deploy;--branch 进预览(P2)
fleetly pages list | get <name> | url <name> | logs <name> [--follow] | build-logs <name>
fleetly pages delete <name>                                        # = App 收口级联零孤儿(FB-1 纪律沿 App 面)
```

- **URL 派生约定**：`<name>-<seq>.<base_domain>`（ADR-0070 名基可读 id 先例；`<seq>` 使同名重建不复用 host）。base_domain 配置键形态见 §6.3。**TLS 诚实边界**：逐 host LE 换发（现 auto resolver 面不动），不做通配证书——DNS-01 需要 DNS 商集成面，量级需求实锤再立（§6.6 同族）。
- **Console**：Pages 页（Apps/Databases/（未来）Functions 平级，ADR-0044 最小面起步）——列表 + 详情（URL CopyButton、构建史、GitHook 状态）+ 创建向导（git URL/upload 两形态）。「Pages」作产品线名与 console 页面泛称的消歧进 P4 词条。
- **P3 服务语义**：`_redirects`（状态码 + 路径映射基本形态）与 `_headers`（路径键值对）子集进 static builder 的 Caddyfile 生成端——**材料半边，零 API 零引擎面**（竞品文件格式按本义豁免，netlify 约定）；immutable cache-control 由构建端内容寻址文件名约定承载（资产指纹命名建议进文档，v1 不执法）。高级形态（代理重写/头条件匹配）不做——需求实锤再扩。

## 5. P2：预览部署环（灵魂件，Phase 2）

- **机制**：GitHook 过滤面扩「预览分支通配」（现单分支等值过滤）→ 命中即铸**短命预览 App**（source = git@`<branch>`、builder = static、Route host = `<name>-<branch-slug>-<seq>.<base_domain>`）→ 生产站点行与路由不动；预览与生产同 Revision 纪律（内容寻址去重，ADR-0064 红利自动覆盖）。
- **回收双通道**：①事件回收——merge/close/分支删除（webhook intake 现只解析 push/ping，**PR 事件是 GitHub 特有 payload**：解析进 GitHook 接收器 only-add；非 GitHub git host 以 ②TTL 兜底降级——两 Runtime/两 host 族诚实分级，Functions §6 同款口径）；②TTL 兜底由 hygiene 环扫（SweepTerminalTaskCarriers 先例；注意 Task TTL 是 Run 生命周期语义，预览回收是 App 级联收口复用——不混用两词）。
- **配额**：MaxPreviewAppsPerSite（新）+ 项目 App 配额自动覆盖（预览 App 即 App 行）。
- **观测**：预览 App 的构建/日志全走既有面；生产页与预览页 Console 分栏（详情页「预览环境」段列活跃预览 + 各自 URL）。

## 6. 开放问题（请 review 逐条给答）

1. **站点/策略行的家**（P2 前必须裁）：a) App 行加预设标记（侵入 App 聚合面）vs b) **薄 pages 行**（App 指针 + 预览策略 + URL 约定——非执行实体，受管策略行）vs c) 纯约定（builder=static 即 Pages——弱：预览策略与 Pages 枚举无处安放，Console 过滤视图脆）。**倾向 b**；P1 可先零行（CLI 糖 + Console 按 builder=static 过滤的临时视图）。
2. **词汇（P4）**：Pages 词条入册文案 + `site` 避让声明（本提案域内指称用什么词——「站点」中文散文 / 英文页面文案怎么写）+ console 页面泛称消歧——是否随裁决一并定稿？
3. **base_domain 配置键**：`pages.base_domain` 独立 vs `delivery.base_domain` 统一（Functions Phase 2 `functions.base_domain` 同题）——先到者定形，还是现在就统一成族键？
4. **P5 触发器**：闲置成本换轨（App → Function 缩零）按什么信号立案——站点数阈值、闲置比观测，还是用户实锤？与 Functions Phase 2 唤醒方向裁决（甲/乙候选）的时序耦合怎么排？
5. **上传构建纪律**：512MiB/4GiB 沿用还是 Pages 专用档（静态产物通常远小，可收紧）？git clone 深度/submodule 沿 App 构建链现状，不另立。
6. **`_redirects`/`_headers` 子集边界（P3）**：本提案建议 v1 只做基本形态（§4）；splats/条件/代理重写不做——是否同意此刀口？

## 7. 分期

- **Phase 0**：P4 词汇批（词条 + 避让 + 消歧 + 守卫同步）。
- **Phase 1（MVP）**：P1 CLI/Console/URL 约定 + P3 服务语义子集 + e2e 腿（git 形态 push 自动重部署 / upload 形态往返 / SPA 回退）。
- **Phase 2**：P2 预览部署环（§6.1 行归宿裁后）+ PR 事件面 + 配额。
- **Phase 3**：P5 闲置成本换轨（视 Functions Phase 2 唤醒落地，站点 App→Function 换轨 ADR）。

## 8. 验收锚（实施完成后逐条核）

1. e2e 全链腿：`pages create --git --wait` → 生产 URL 200；push 新 commit → 自动重部署且**内容同则零滚**（ADR-0064 断言）；upload 形态完整往返；SPA 深链回退 200；`pages delete` 后载体/Route/GitHook/构建产物零孤儿。
2. 预览腿（Phase 2）：branch push → 预览 URL 200 且生产不动；merge/close → 事件回收零孤儿；拔 webhook 后 TTL 兜底腿仍回收；配额超限诚实拒。
3. 服务语义腿：`_redirects` 命中重定向状态码；`_headers` 响应头生效；指纹资产 cache-control。
4. 守卫批：CLI 双形态 golden、词汇批双向保鲜、预览回收反扫（FB-1 同型）、配额执法。
5. dogfood：staging 用 Pages 托管一个真实静态站（候选：fleetly 自身 landing/文档站）。
6. 每期复盘重跑 §3 deletion test（P5 换轨若发生，重跑时按 Function 轴重判）。
